合规说明

透明，且可验证。

AMEFYS 是非官方 DOTA 2 辅助工具，严格遵守 Valve 用户协议。这页详细说明我们做什么、不做什么、为什么不会被 VAC 封号。

最后更新：2026-10-17

简要结论

AMEFYS 只通过 Valve 官方支持的 GSI（Game State Integration）接口读取数据，不修改游戏内存、不注入 DLL、不拦截网络、不读取敌方隐藏信息。发送聊天时，AMEFYS 先把文字放进剪贴板，再替你按下打开聊天框、粘贴、发送这几个键，用的是游戏自带的聊天框 — 跟你自己打字发出去完全一样。

如果你在意"装这个软件会不会被 VAC 封号" — 答案是不会。我们做的事情在 Valve 的政策允许范围内，跟你装一个 Steam Workshop 上的 HUD 修改器同等性质。

我们做什么 / 不做什么

✓

我们做的事情

  • 通过官方 GSI 接口读取你的英雄、装备、对局状态
  • 用本地规则 + AI 给出装备推荐
  • 调用翻译 API 翻译你看到的聊天内容
  • 替你把选好的文字粘贴进游戏自带的聊天框并发送（剪贴板 + 模拟按键）
  • 「关键时间提醒」只读对局时钟（GSI 的 map.clock_time）提醒你自己；其中「到点自动发送到队伍频道」是全应用唯一一项按游戏状态自动发消息的选项 —— 默认关闭、需手动开启并确认警告、每个节点每次仅发一条带时间的预制短语
  • 在本地 SQLite 存对局历史（可导出 / 删除）
  • 登录用户的对局数据可选择同步到 Supabase 云端
✗

  • 注入 DLL / dylib / 任何代码到游戏进程

外部数据、图片和识别功能

除了 GSI，AMEFYS 还用到 OpenDota 的公开统计和 Valve 的英雄、装备图片，另外有两种需要"看画面"的识别功能。下面逐条说明它们读的是什么、在哪里处理、会不会离开你的设备。

OpenDota 公开对局统计

选人推荐里的胜率、克制和搭配数据，来自 OpenDota 公开的历史对局。我们每天用自动任务从 OpenDota 拉取最近 7 天的公开比赛，只按英雄组合统计场次和胜场，做成一份数据包放在 cdn.amefys.com。你的电脑每天检查一次有没有新数据包，安装包里也自带一份。这份数据只有英雄和胜负的计数，不含任何玩家的账号或名字。出装推荐用到的出装热度、英雄对位等统计同样来自 OpenDota，在发版时打包进安装包。

算推荐本身用不到你的 Steam 信息。只有在你自己去设置里填了好友代码之后，下面几处才会拿它去 OpenDota 查询：设置页核对这串代码对应的是哪个账号、「从 OpenDota 获取」段位、「导入全部历史对局」，以及选人面板里的「使用我的 Steam 数据」开关（默认关闭，打开后每天最多查一次，按你的段位和各英雄场次调整推荐）。这些查询由你的电脑直接发给 OpenDota，好友代码不经过 AMEFYS 的服务器。查到的段位和英雄战绩保存在你本机；导入的对局进入历史对局，和你的其他对局一样按隐私政策里「对局历史」一栏处理。OpenDota 只能查到你在 Dota 2 里打开了「公开比赛数据」的战绩。

英雄、装备的图片和名称

英雄头像和装备图标来自 Valve 公开的图片服务器（cdn.cloudflare.steamstatic.com）。为了让国内网络也能顺利加载，我们在 cdn.amefys.com 放了一份同样的图片：电脑版的选人面板和手机版选人页先从这里读取，读不到时再回到 Valve 的地址；本站的英雄、装备页面直接用这份图片；电脑版对局中的出装推荐等界面直接从 Valve 的地址加载。安装包里不打包这些图片。英雄和装备的中文名称取自 Dota 2 官网公开的数据，和游戏里的叫法一致。

这些图片、名称以及其他 Dota 2 相关素材的版权归 Valve Corporation 所有。AMEFYS 是独立开发的非官方工具，与 Valve 没有任何关联。

聊天文字识别（OCR）

想翻译队友打的字时，可以用识别功能把游戏聊天框里的文字读出来。这个功能默认关闭，而且只在你主动触发时才截图：按下识别快捷键，或在设置里点测试的时候。每次只截屏幕上的一块区域：默认是你当场用鼠标框出来的那一块，也可以改成你事先设好的固定聊天区域。截图交给电脑系统自带的文字识别（macOS 的 Vision、Windows 自带的 OCR），在你本机完成，截图不上传；Windows 上识别需要先存成临时文件，识别完马上删除。识别出的文字只有在需要翻译时才会发往翻译服务，具体见隐私政策。

OCR 诊断上报：为了查清"识别或翻译不对劲"到底卡在哪一步，每次识别结束后会生成一条诊断记录，里面只有数字和类别：识别出几行、过滤掉几行、识别的把握程度、拉丁 / 西里尔 / 中日韩各类文字各有多少字、每行翻译成功还是失败及失败原因、所选的识别和翻译语言、翻译通道和识别引擎、App 与系统版本、框选区域的宽和高。不含识别出的任何文字、截图、框选在屏幕上的位置和玩家名。这条记录只在你登录后才会上传到我们的数据库，会关联你的账号，30 天后自动删除。另外，识别出错、文字全部被过滤或翻译失败时，还会把错误类别和这些数字发给错误上报服务 Sentry。它和「发送匿名崩溃报告」共用一个开关，默认开启，在 设置 → 数据与隐私 里关掉后立即停止。OCR 设置里的「复制诊断信息」按钮只把最近 10 次的诊断摘要复制到你自己的剪贴板，发不发给我们由你决定。

手机版选人拍照识别

在手机版选人页（amefys.com/bp）里，你可以对着电脑屏幕上的选人界面拍照，或者从相册选一张图，让它认出已经选了、禁了哪些英雄。识别在你手机的浏览器里完成，照片和相机取景画面不上传、不保存。手机只会从 cdn.amefys.com 下载一份公开的英雄头像参考数据用来比对。出错时的「复制诊断信息」只把图片尺寸、耗时、识别分数、浏览器版本这类信息复制到你自己的剪贴板，不含照片、英雄和玩家名。

文字识别和拍照识别看的都是屏幕上已经显示出来的画面，也就是你自己本来就能看到的内容：不读游戏内存、不往游戏里注入任何东西、不拦截或修改网络流量。

跟 Valve 政策的关系

Valve 的 Steam 用户协议 第 6 节"软件使用规范"允许第三方工具，只要它们：

…不修改 Steam 客户端或任何 Subscription 软件、不获取超出 Valve 公开接口范围的游戏状态信息、不干扰其他玩家的体验、不用于商业作弊…— Steam Subscriber Agreement §6（节选）

AMEFYS 的每一项功能都在这条规则的"允许"侧 — 我们没有理由相信 Valve 会反对一个只读自己的 GSI 数据 + 通过游戏内置脚本发送预制文字的工具。

如果你对某个具体功能是否合规有疑虑，直接发邮件给我们，我们会逐条说明。

会不会被 VAC 封号？

不会。VAC（Valve Anti-Cheat）的检测目标是"修改游戏内存 / 注入代码 / 文件签名异常"。AMEFYS 不做这些事 — 它是一个独立桌面进程，跟 DOTA 2 通过 HTTP 协议（GSI）交换 JSON 数据，跟 Twitch 直播插件、SteelSeries OLED 显示工具的工作方式完全等价。

类似的 GSI 工具（Overwolf 系列、DOTA Plus 第三方插件、StreamProfile 等）已经在 DOTA 2 社区合规使用多年，没有任何 VAC 误封先例。
